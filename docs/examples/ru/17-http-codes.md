## Таблица

| Код | Код ошибки | Исключение | Повторяется сама |
|---|---|---|---|
| 200 | — | нет, вернётся объект | — |
| 400 | `invalid_request` | `BadRequest` | нет |
| 401 | `invalid_credentials` | `Unauthorized` | нет |
| 403 | `forbidden` | `Forbidden` | нет |
| 404 | `not_found` | `NotFound` | нет |
| 405 | — | `APIError` | нет |
| 415 | — | `APIError` | нет |
| 429 | `too_many_requests` | `RateLimited` | да |
| 500 | `internal_server_error` | `ServerError` | да |
| 202 | — | `ResponseProcessing` | да |
| нет ответа | — | `TransportError` | да |

## 200 и статус pending

Успешный ответ не означает, что операция завершена. Платёж возвращается в
статусе `pending`, пока плательщик не подтвердил оплату.

```python
payment = kassa.payments.create(params)

payment.is_pending             # ждём плательщика
payment.is_waiting_for_capture # деньги захолдированы
payment.is_succeeded           # деньги у магазина
payment.is_canceled            # деньги у плательщика
```

Узнать о смене статуса можно двумя способами, и правильный - первый:

**Уведомление.** Подписка на `payment.succeeded`, обработчик описан в
[примерах по уведомлениям](13-webhooks.md).

**Опрос.** Если уведомления недоступны, повторяйте `get` с растущим
интервалом. Опрос в тесном цикле упрётся в 429.

```python
import time

def wait_for_final_status(kassa, payment_id, attempts=10):
    """Дождаться финального статуса, увеличивая паузу по Фибоначчи."""
    previous, delay = 1, 1
    for _ in range(attempts):
        payment = kassa.payments.get(payment_id)
        if not payment.is_pending:
            return payment
        time.sleep(delay)
        previous, delay = delay, previous + delay
    return None
```

Если объект застрял в `pending` дольше отведённого срока подтверждения - это
повод писать в поддержку ЮKassa, а не продолжать опрос.

## 400: ошибка в запросе

Нарушены синтаксис или логика: нет обязательного параметра, значение не того
формата, переданы взаимоисключающие поля, что-то не так с ключом
идемпотентности.

```python
from yookassax import BadRequest

try:
    payment = kassa.payments.create(params)
except BadRequest as error:
    logger.error(
        "ЮKassa отклонила запрос: %s, поле %s, request_id %s",
        error.description,
        error.parameter,
        error.request_id,
    )
```

Повторять бессмысленно: тот же запрос даст тот же ответ. Библиотека такие
ошибки и не повторяет. Чинится в коде, а не в рантайме.

`parameter` указывает поле, из-за которого запрос отклонён - с него и стоит
начинать разбор.

## 401: аутентификация

Данные для аутентификации не приняты. Причина зависит от способа.

**HTTP Basic (свой магазин).** Нет идентификатора или ключа, они перепутаны
местами, ключ устарел, идентификатор от другого магазина.

**OAuth (партнёрское приложение).** Токен не передан, устарел, отозван
пользователем, или приложение, для которого он выдан, удалено.

```python
from yookassax import Unauthorized

try:
    settings = kassa.settings.get()
except Unauthorized:
    # Для партнёрского приложения это "переподключите магазин",
    # для своего - "проверьте ключи".
    ...
```

Проверять ключи стоит на старте приложения, а не на первом платеже:

```python
settings = kassa.settings.get()
logger.info("магазин %s, тестовый: %s", settings.account_id, settings.test)
```

## 403: не хватает прав

Запрос правильный, но операция магазину не разрешена. Типичные случаи:
рекуррентные платежи не подключены, передача данных карты без сертификата
PCI DSS, для OAuth - право не запрашивалось при регистрации приложения.

```python
from yookassax import Forbidden

try:
    payment = kassa.payments.create({**params, "payment_method_id": saved_method_id})
except Forbidden as error:
    logger.error("Операция не разрешена магазину: %s", error.description)
```

Ошибка постоянная: лечится настройками магазина или набором прав приложения,
а не повтором запроса.

## 404: объекта нет

Объект не существует либо создан в другом магазине. Второе встречается чаще,
чем кажется: например, ключи от боевого магазина, а идентификатор платежа из
тестового.

```python
from yookassax import NotFound

try:
    payment = kassa.payments.get(payment_id)
except NotFound:
    ...
```

Иногда 404 приходит на только что созданный объект - обращение попало в
реплику. Помогает повтор через секунду, но чаще это всё же чужой
идентификатор.

## 405 и 415

`405` - неверный HTTP-метод, `415` - неверный `Content-Type`. При работе через
библиотеку они не появляются: и метод, и заголовки формирует она сама.

Встретить их можно только на своём вызове неописанного эндпоинта:

```python
from yookassax import Operation

operation = Operation(method="GET", path="/payments/{id}/cancel")   # так нельзя
```

Отмена платежа - это POST. Библиотека передаст то, что вы указали, и ЮKassa
ответит 405.

## 429: слишком часто

Превышена частота запросов. Библиотека повторяет такой запрос сама, с
экспоненциальной паузой и дрожанием - дрожание нужно, чтобы пачка клиентов,
одновременно получивших 429, не пошла на второй круг тоже одновременно.

```python
kassa = YooKassa(shop_id="...", secret_key="...", retries=5)
```

Если 429 приходит постоянно, повторы не помогут: надо снижать частоту.
Обычная причина - опрос статусов в тесном цикле вместо уведомлений.

## 500: результат неизвестен

Технические неполадки на стороне ЮKassa. Главное здесь: **500 не означает, что
операция не прошла**. Платёж мог быть создан, а ответ потеряться.

Библиотека повторяет запрос с тем же ключом идемпотентности, поэтому повтор не
создаёт второй платёж. Если попытки кончились - выясняйте состояние, а не
создавайте заново.

```python
from yookassax import ServerError, TransportError

key = f"order-{order_id}"

try:
    payment = kassa.payments.create(params, idempotency_key=key)
except (ServerError, TransportError):
    # Тот же ключ: если платёж создан, вернётся он же.
    payment = kassa.payments.create(params, idempotency_key=key)
```

Если 500 не проходит больше получаса - это обращение в поддержку с
`request_id`, а не бесконечный повтор.

## Про ключ идемпотентности при ошибках

Правило одно, и оно противоположно интуиции:

**Исправили запрос - новый ключ.** После 400, 403, 404, 405 и 415 запрос
меняется, а значит ключ должен быть другим. Старый ключ привязан к старому
телу, и ЮKassa может вернуть прежний результат.

**Повторяете тот же запрос - тот же ключ.** После 500, 429 и обрыва связи тело
не менялось, и повтор с тем же ключом защищает от второго платежа.

Библиотека проставляет ключ сама и при своих повторах использует тот же. Свой
ключ нужен, когда повтор возможен со стороны вашего кода - тогда собирайте его
из идентификатора заказа, а не случайным:

```python
kassa.payments.create(params, idempotency_key=f"order-{order_id}")
```

Случайный ключ при повторе будет другим, и защита от двойного платежа
перестанет работать.
