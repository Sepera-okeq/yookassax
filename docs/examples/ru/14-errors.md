## Иерархия исключений

```
YooKassaError                базовая, ловите её, если детали не важны
    ConfigurationError       клиент собран неверно
    TransportError           ответа не было вообще
    APIError                 API ответило ошибкой
        BadRequest           400
        Unauthorized         401
        Forbidden            403
        NotFound             404
        Gone                 410
        RateLimited          429
        ResponseProcessing   202
        ServerError          500
```

```python
from yookassax import (
    BadRequest,
    Forbidden,
    NotFound,
    TransportError,
    YooKassaError,
)

try:
    payment = kassa.payments.create({...})
except Forbidden:
    ...
except BadRequest as error:
    ...
except TransportError:
    ...
except YooKassaError:
    ...
```

## Разбор ошибки

У любой ошибки API разобрано тело ответа.

```python
from yookassax import APIError

try:
    payment = kassa.payments.create({"amount": {"value": "0.00", "currency": "RUB"}})
except APIError as error:
    print(error.status)        # 400
    print(error.code)          # invalid_request
    print(error.description)   # Сумма меньше минимальной
    print(error.parameter)     # amount
    print(error.request_id)    # идентификатор запроса для поддержки
    print(error.payload)       # тело ответа целиком
```

`request_id` стоит писать в лог: с ним поддержка ЮKassa найдёт запрос у себя.

## Что повторяется само

Клиент повторяет то, что почти наверняка пройдёт со второй попытки:

| Код | Что означает | Повторяется |
|---|---|---|
| 202 | запрос принят, ещё обрабатывается | да |
| 429 | превышена частота запросов | да |
| 500 | сбой на стороне ЮKassa | да |
| обрыв связи | ответа не было | да |
| 400 | ошибка в запросе | нет |
| 401 | неверный ключ | нет |
| 403 | операция не разрешена | нет |
| 404 | объекта нет | нет |

Ошибки данных не повторяются намеренно: второй такой же запрос даст тот же
ответ, а на платёжных путях лишние попытки только мешают разбираться.

Пауза между попытками растёт экспоненциально и слегка дрожит. Дрожание нужно,
чтобы пачка клиентов, одновременно получившая 429, не пошла на второй круг тоже
одновременно.

## Обрыв связи при создании платежа

`TransportError` вынесен в отдельный тип не случайно. Если создание платежа
упало с ним, **неизвестно, создан платёж или нет**: запрос мог дойти до
ЮKassa, а ответ потеряться.

Клиент сам повторит запрос с тем же ключом идемпотентности, поэтому второго
платежа не возникнет. Но если попытки кончились, состояние остаётся неясным.

Правильная реакция: не создавать платёж заново вслепую, а выяснить состояние.

```python
from yookassax import TransportError

idempotency_key = f"order-{order_id}"

try:
    payment = kassa.payments.create(params, idempotency_key=idempotency_key)
except TransportError:
    # Повторяем с ТЕМ ЖЕ ключом: если платёж уже создан,
    # ЮKassa вернёт существующий, а не создаст второй.
    payment = kassa.payments.create(params, idempotency_key=idempotency_key)
```

Именно поэтому ключ идемпотентности стоит собирать из идентификатора заказа, а
не оставлять случайным: случайный ключ при повторе будет другим.

## Настройка повторов

```python
kassa = YooKassa(
    shop_id="123456",
    secret_key="live_...",
    retries=5,      # всего попыток, считая первую
    timeout=10.0,   # таймаут одного запроса
)
```

`retries=1` отключает повторы полностью.

Для фоновых задач имеет смысл увеличить число попыток, для обработчика веб-
запроса наоборот уменьшить: пользователь не должен ждать три круга ожидания.

## Поля, которых нет в модели

ЮKassa добавляет поля в ответы молча. Разбор от этого не падает: лишнее
остаётся в `raw` и доступно через `extra()`. Но узнать об этом иначе нельзя,
поэтому библиотека предупреждает.

```python
payment = kassa.payments.get(payment_id)
# UnknownFieldWarning: Payment: в ответе API есть поля, которых нет в модели:
# loyalty_bonus. Значения доступны через extra(), но, возможно, стоит
# обновить yookassax.

payment.extra("loyalty_bonus")   # значение уже доступно
```

Предупреждение указывает на строку вашего кода, а не на внутренности
библиотеки: по ней видно, какой именно запрос принёс новое поле.

**Спама не будет.** О каждой паре "модель плюс поле" говорится один раз за
время жизни процесса: страница из ста платежей с новым полем даст одну строку,
а не сто.

Это предупреждение, а не ошибка: ничего не ломается и делать ничего не нужно.
Разумная реакция это посмотреть, что появилось, и обновить `yookassax`, когда
поле понадобится.

Отключается штатным фильтром:

```python
import warnings
from yookassax import UnknownFieldWarning

warnings.filterwarnings("ignore", category=UnknownFieldWarning)
```

Обратное тоже работает: в тестах предупреждение можно превратить в ошибку,
чтобы изменение ответа API не прошло незамеченным.

```python
warnings.filterwarnings("error", category=UnknownFieldWarning)
```

Если логи собираются через `logging`, предупреждения удобно направить туда же:

```python
import logging

logging.captureWarnings(True)
```

## Частые ошибки

**403 при сохранении способа оплаты или списании по нему.** Магазину не
подключены рекуррентные платежи. Ошибка постоянная, повторять бессмысленно,
нужно обращаться в ЮKassa.

```python
except Forbidden as error:
    logger.error("Рекуррент не подключен: %s", error.description)
```

**401 на всех запросах.** Ключ не тот: секретный ключ магазина там, где нужен
OAuth-токен, или наоборот. Проверяется вызовом `kassa.settings.get()` на старте.

**400 с parameter в ответе.** Смотрите, какое поле не понравилось:

```python
except BadRequest as error:
    logger.error("Поле %s: %s", error.parameter, error.description)
```

**404 на только что созданный объект.** Бывает при обращении к реплике сразу
после записи. Помогает повтор через секунду, но чаще это признак того, что
идентификатор взят не оттуда.
